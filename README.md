# Tesseract Chess

Neon 3D Raumschach and four-dimensional mathematical chess, built for desktop and mobile. Independent, dependency-free ES modules; no account, external AI, or runtime CDN.

Play: https://nathan-culver.github.io/Tesseract-Chess/

## Modes

- **3D Raumschach:** 5×5×5, 20 pieces per side. Rook slides on one axis, bishop on two, unicorn on three, queen on any combination. Knight leaps (2,1,0); king has 26 adjacent cells. Forward-only pawns move in Y/Z and capture ±X+forward Y, ±X+forward Z, or forward Y+Z. Promotion requires both far Y/Z edges.
- **4D mathematical chess:** 4×4×4×4, 16 pieces per side. Follows the starting arrangement, odd-axis rook, even-axis bishop, planar knight and two-forward-direction pawns in [Four Dimensional Chess (2009)](https://math.iit.edu/~breiniger/Chess/chess-basicmath.pdf). Coordinates are small file/rank X/Y and big file/rank Z/W. White moves +Y/+W, Black −Y/−W. Pawns capture one forward step plus ±X/±Z, promoting at both far ranks.
- **4D king rules:** Fortress (default; home 2×2×2×2 region with X/Z central), unrestricted (80 adjacent cells), or orthogonal (one axis per step). The PDF discusses alternatives rather than prescribing one universal king rule.
- White starts. No castling, initial double pawn step, or en passant. Kings are protected, checked and checkmated; never captured.
- Checkmate wins. App draw conventions automatically draw at stalemate, threefold repetition, 100 halfmoves without pawn move/capture, or bare kings. Same-device players can agree to draw.
- Optional **25/50/75/100 capture-point targets**, off by default. Values: pawn 1, knight/bishop/unicorn 3, rook 5, queen 9. Promotion earns no points; capturing a promoted piece earns its current value. Checkmate takes priority. Starting capturable armies total 47 points in 3D and 39 in 4D: higher targets need promotions to become reachable.

The [3D chess overview](https://en.wikipedia.org/wiki/Three-dimensional_chess) was also supplied as a reference. Pawn conventions, 4D king choice, point values, targets and draw rules are explicitly documented custom choices; there is no single universal multidimensional chess ruleset.

## Controls

Drag empty cube space to orbit; Shift/right-drag to pan; scroll/pinch to zoom. View offers one-finger pan, reset, zoom, glow, and black/white/pink/grey/brown backgrounds. Full cube displays all XYZ layers, with optional single layer isolation. Flat layer supports accurate input; **All boards** provides accessible buttons for all 125/256 cells. In 4D, W selects a 3D slice. Select a piece, change W, and choose a legal cross-slice destination; switching slices preserves selection. The precise Piece/Legal destination dropdowns reach every legal cell.

Drag a piece directly onto a highlighted destination without selecting it first. Piece silhouettes take priority over overlapping empty grid points. Drops snap only to legal cells; an invalid drop is marked with a pink ring. Its preview stays translucent until tapped or confirmed. Pick up the preview and drop it elsewhere to retry; invalid drops keep the preceding preview. Disable confirmation in View for immediate legal drops and destination taps. Dragging remains available. Promotions always retain preview so the player can choose the promoted piece. Unicorns use a horse silhouette with a **U** badge, distinct from knights.

Mobile Play/View/Game tabs stay within the cube and collapse out of the way. All boards scrolls independently. Keyboard users can use the Piece/Legal destination dropdowns and Confirm, or the accessible board cells. Cube keyboard shortcuts: +/− zoom and Home reset.

## AI, time and saves

Easy, Normal, Hard run entirely locally in a module worker. Hard uses iterative alpha-beta search for about six seconds. It is a heuristic engine, not a rated engine. A busy indicator, hints and stop control are included. Local pass-and-play is supported. Online multiplayer is deferred.

Untimed, total allowance, per-move increment, or Japanese-style overtime periods. Same-side clocks pause when hidden, in dialogs, replay, or with Pause. Local clocks are not tamper-resistant. Undo retains the last twenty moves, including after reload; AI undo returns to the preceding human turn. Replay is read-only.

Automatic checkpoints retain the latest completed move, ten moves earlier, twenty moves earlier. One manual localStorage slot and ten device slots support export/import of versioned `.tch` JSON files. Autosaves and numbered slots use IndexedDB. All keys/caches are Chess-specific and separate from Tesseract Go. `?test=1` isolates QA game saves. View preferences are shared between QA and normal play.

Open the hosted game once until **Ready for offline play**; the service worker caches all game assets. Then local AI and local play work offline. Clearing browser data removes saves: export backups. The standalone `Tesseract-Chess.html` generated by `npm run portable` embeds all runtime modules and AI; file-origin storage behavior varies by browser, so the hosted edition is preferred for durable saves.

## Run and verify

Node 22+, no dependency installation:

```
npm run dev
npm run check
npm test
npm run portable
```

GitHub Pages is configured for GitHub Actions. `.github/workflows/pages.yml` checks scripts, runs rules/clock/board/storage tests and deploys only runtime assets. Rendering uses perspective-projected canvas geometry and luminous chess silhouettes rather than WebGL, with a DOM board overview.
